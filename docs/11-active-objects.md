# 11. Active Objects and the Active Scheduler

> **Scope:** asynchronous programming on Symbian — `CActive`, `CActiveScheduler`, `TRequestStatus`, priorities, cancellation, long-running tasks, synchronous waits, nested loops (`CActiveSchedulerWait`), and the common panics.
> **Why it matters:** nearly every Symbian API that takes time is asynchronous. GUI apps and servers are event loops of active objects. Threads are rarely needed.

## 11.1 The model

* An **asynchronous function** starts a request and returns immediately. It takes a `TRequestStatus&`; the request is usually serviced by another thread or a server.
* The thread's **active scheduler** runs an event loop waiting on the thread's **request semaphore**.
* Each **active object** (AO) owns one `TRequestStatus iStatus` and can have **at most one request outstanding**.
* When a request completes, the service provider writes the result into `iStatus` and signals the thread. The scheduler finds the highest-priority AO whose request has completed and calls its **`RunL()`**.
* This is **cooperative (non-pre-emptive) multitasking within one thread**: `RunL()` is never interrupted by another `RunL()` in the same thread. A long `RunL()` blocks everything else (including UI redraws and key handling — and on S60 a UI thread blocked for ~10 s gets a `ViewSrv 11` panic).

```
       Thread
  ┌──────────────────────────────────────────────┐
  │ CActiveScheduler: loop { WaitForAnyRequest(); │
  │   find highest-priority AO with completed     │
  │   request; clear its active flag; RunL(); }   │
  │                                              │
  │  AO1 (prio 20) ─ iStatus ◄── server A        │
  │  AO2 (prio 0)  ─ iStatus ◄── timer           │
  └──────────────────────────────────────────────┘
```

Advantages over threads: no locking, low memory (no extra stacks), cheap context switches. Most system code — including Symbian's servers — is built this way.

## 11.2 The scheduler

One `CActiveScheduler` per thread that uses AOs. **GUI applications and servers already have one** in the main thread. Console programs and any thread you create must install one:

```cpp
CActiveScheduler* scheduler = new (ELeave) CActiveScheduler;
CleanupStack::PushL(scheduler);
CActiveScheduler::Install(scheduler);

CMyTimer* timer = CMyTimer::NewLC();
timer->Start(TTimeIntervalMicroSeconds32(10000000));   // issue the first request

CActiveScheduler::Start();       // blocks here, dispatching RunL()s, until Stop()

CleanupStack::PopAndDestroy(2, scheduler);
```

| Static function | Purpose |
|-----------------|---------|
| `Install(s)` | Make `s` the scheduler of the current thread |
| `Current()` | Get it |
| `Add(CActive*)` | Register an AO (normally in its constructor / `ConstructL`) |
| `Start()` | Run the loop (nestable) |
| `Stop()` | Make the innermost `Start()` return after the current `RunL()` finishes |
| `Halt(code)` (9.x) | Stop with an exit code |
| `Error(TInt)` (virtual) | Called when `RunError()` returns an error; default **panics `E32USER-CBase 47`**. Derive your own scheduler to override it (e.g. log and continue). `CEikonEnv`/`CAknEnv` do this for GUI apps (they show an error note). |

**If you call `Start()` when no AO has an outstanding request, the thread hangs forever.**

## 11.3 Writing an active object

Derive from `CActive` (itself a `CBase`). It provides:

| Member | Notes |
|--------|-------|
| `CActive(TInt aPriority)` | Constructor takes the priority |
| `TRequestStatus iStatus` | Pass to the async function. `KRequestPending` while outstanding; then a result code. **Read it in `RunL()`; never set it yourself** (except via `User::RequestComplete`). |
| `SetActive()` | Mark that a request is outstanding. **Call immediately after issuing the request.** |
| `IsActive()` | Is a request outstanding? Check before issuing a new one. |
| `RunL()` *(pure virtual)* | Handle completion. May leave. |
| `DoCancel()` *(pure virtual)* | Cancel the outstanding request at the service provider. Only called via `Cancel()` and only if active — no `IsActive()` check needed inside. |
| `Cancel()` | If active: calls `DoCancel()`, **waits** for the request to complete (with `KErrCancel`), clears the active flag. No-op if not active. `RunL()` is **not** called for a cancelled request. |
| `RunError(TInt aError)` *(virtual)* | Called by the scheduler if `RunL()` leaves. Return `KErrNone` if handled; returning the error passes it to `CActiveScheduler::Error()` (→ panic 47 by default). The default implementation returns `aError`. |
| `Priority()`, `SetPriority()`, `IsAdded()`, `Deque()` | Rarely needed; the destructor dequeues automatically. |

### Template (timer-based, as generated by Carbide.c++ "Active Object Class")

```cpp
// MyActive.h
#include <e32base.h>   // CActive
#include <e32std.h>    // RTimer

class CMyActive : public CActive
    {
public:
    static CMyActive* NewL();
    static CMyActive* NewLC();
    ~CMyActive();

    void StartL(TTimeIntervalMicroSeconds32 aDelay);

private:
    CMyActive();
    void ConstructL();

private: // from CActive
    void RunL();
    void DoCancel();
    TInt RunError(TInt aError);

private:
    enum TState { EUninitialized, EInitialized, EError };
    TInt   iState;
    RTimer iTimer;     // the asynchronous service provider
    };
```

```cpp
// MyActive.cpp
#include "MyActive.h"

CMyActive::CMyActive() : CActive(EPriorityStandard)
    {
    }

CMyActive* CMyActive::NewLC()
    {
    CMyActive* self = new (ELeave) CMyActive();
    CleanupStack::PushL(self);
    self->ConstructL();
    return self;
    }

CMyActive* CMyActive::NewL()
    {
    CMyActive* self = CMyActive::NewLC();
    CleanupStack::Pop(self);
    return self;
    }

void CMyActive::ConstructL()
    {
    User::LeaveIfError(iTimer.CreateLocal());
    CActiveScheduler::Add(this);        // register last, after leaving init succeeded
    }

CMyActive::~CMyActive()
    {
    Cancel();                           // ALWAYS first in the destructor
    iTimer.Close();
    }

void CMyActive::DoCancel()
    {
    iTimer.Cancel();
    }

void CMyActive::StartL(TTimeIntervalMicroSeconds32 aDelay)
    {
    Cancel();                           // or: if (IsActive()) User::Leave(KErrInUse);
    iState = EUninitialized;
    iTimer.After(iStatus, aDelay);
    SetActive();
    }

void CMyActive::RunL()
    {
    User::LeaveIfError(iStatus.Int());  // or switch on iStatus.Int()
    if (iState == EUninitialized)
        {
        // first completion
        iState = EInitialized;
        }
    else if (iState != EError)
        {
        // subsequent completions
        }
    iTimer.After(iStatus, 1000000);     // re-issue: 1 s
    SetActive();
    }

TInt CMyActive::RunError(TInt aError)
    {
    iState = EError;
    // log / notify the observer
    return KErrNone;                    // handled — don't panic
    }
```

### Rules
1. **Add to the scheduler** (`CActiveScheduler::Add(this)`) before issuing the first request.
2. **One outstanding request per AO.** Check `IsActive()` or `Cancel()` before issuing a new one. Issuing a second request → **`E32USER-CBase 42`** (if you call `SetActive()` twice) or a stray signal.
3. **Call `SetActive()` right after issuing a request.** Forgetting it → when the request completes the scheduler can't find an active AO → **stray signal, `E32USER-CBase 46`**.
4. **Pass `iStatus`**, not a local `TRequestStatus`.
5. **Call `Cancel()` first in the destructor**, before closing the service provider. Deleting an active AO → **`E32USER-CBase 40`**.
6. **Implement `DoCancel()`** with the provider's matching cancel function (`RTimer::Cancel()`, `RSocket::CancelRecv()`, `RFile::ReadCancel()` …).
7. Keep `RunL()` short. Split long work into steps (§11.5).
8. Handle errors: inspect `iStatus.Int()`; implement `RunError()` if `RunL()` may leave.
9. Never call `User::WaitForRequest()` on an AO's `iStatus` while it's managed by the scheduler.

### Priorities (`CActive::TPriority`)

| Value | Use |
|-------|-----|
| `EPriorityIdle` (-100) | Background processing that runs only when nothing else is ready |
| `EPriorityLow` (-20) | |
| `EPriorityStandard` (0) | **Default — use unless you have a reason** |
| `EPriorityUserInput` (10) | Handling user input |
| `EPriorityHigh` (20) | |

Priorities only order AOs **within one thread's scheduler** when several are ready at once; they don't pre-empt anything and are unrelated to thread priorities. Absolute values don't matter, only relative order. High-priority AOs that complete frequently can **starve** lower ones.

## 11.4 Service providers

Classes offering async functions — mostly R-class client handles to servers (`RTimer`, `RFile`, `RSocket`, `RConnection`, `RProperty`, `RHostResolver`, `CTelephony`…). Their async functions take a `TRequestStatus&` and come with a cancel function. A typical async API:

```cpp
void RSocket::Recv(TDes8& aDesc, TUint aFlags, TRequestStatus& aStatus);
void RSocket::CancelRecv();
```

Keep any buffer you pass (`aDesc`) alive until the request completes — it's written asynchronously. Make it a member, never a local.

Implementing a provider: store the caller's `TRequestStatus*`, set it to `KRequestPending` when starting (`*status = KRequestPending;`), and complete it later with `User::RequestComplete(status, code)` (same thread) or `RThread::RequestComplete(status, code)` (other thread). Servers do this via `RMessage2::Complete()`.

## 11.5 Long-running tasks: self-completing AOs

Break a long computation into steps; after each step, complete your own request so the scheduler can service other AOs in between:

```cpp
class CLongTask : public CActive
    {
public:
    CLongTask() : CActive(EPriorityIdle) { CActiveScheduler::Add(this); }
    ~CLongTask() { Cancel(); }
    void Start()
        {
        Cancel();
        iStep = 0;
        CompleteSelf();
        }
private:
    void CompleteSelf()
        {
        TRequestStatus* status = &iStatus;
        SetActive();
        User::RequestComplete(status, KErrNone);
        }
    void RunL()
        {
        if (DoOneStepL())          // returns ETrue while there's more to do
            CompleteSelf();
        else
            NotifyFinished();
        }
    void DoCancel()
        {
        // The request is already complete (we completed it ourselves) — nothing to cancel.
        }
    TBool DoOneStepL();
    void NotifyFinished();
    TInt iStep;
    };
```

`CIdle` (callback while nothing else is ready) and `CAsyncCallBack` (one-shot asynchronous callback) are ready-made helpers for the same purpose:

```cpp
iIdle = CIdle::NewL(CActive::EPriorityIdle);
iIdle->Start(TCallBack(CMyClass::IdleStep, this));   // static TInt IdleStep(TAny*): return ETrue to be called again
```

## 11.6 Waiting synchronously

Any async function can be made synchronous:

```cpp
TRequestStatus status;
timer.After(status, 10000000);
User::WaitForRequest(status);           // blocks the thread until status != KRequestPending
User::LeaveIfError(status.Int());

User::WaitForRequest(statusA, statusB); // wait for either (e.g. operation + timeout timer)
User::WaitForAnyRequest();              // wait for any signal to this thread
```

* Blocking the UI thread freezes the app (and risks `ViewSrv 11`). Use only in worker threads, tests, or trivially short waits.
* After waiting on two requests, cancel the one that didn't complete and wait for it too, or you get a stray signal later.
* For plain delays: `User::After(microseconds)` and `User::At(TTime)` (block the thread).

## 11.7 Nested loops: `CActiveSchedulerWait`

To wait for an async result **without** blocking other AOs (e.g. a "modal" operation in a GUI), start a nested scheduler loop:

```cpp
class CSyncOp : public CActive
    {
    ...
    CActiveSchedulerWait iWait;
    };

TInt CSyncOp::RunSyncL()
    {
    IssueRequest();            // async call + SetActive()
    iWait.Start();             // nested loop: other AOs keep running
    return iStatus.Int();      // we get here after AsyncStop()
    }

void CSyncOp::RunL()
    {
    if (iWait.IsStarted())
        iWait.AsyncStop();     // makes iWait.Start() return
    }
```

Never call `CActiveScheduler::Start()` again yourself for this; `CActiveSchedulerWait` (S60 2nd Ed.+) is the supported way. Beware re-entrancy: other `RunL()`s (and UI events) run while you wait. Modal dialogs (`ExecuteLD`) use the same mechanism.

## 11.8 Common timer AOs

* `CTimer` — abstract `CActive` wrapping an `RTimer`: derive, implement `RunL()`, call `After()`/`At()`.
* `CPeriodic` — periodic callback via `TCallBack`.
* `CHeartbeat` — callback synchronised to the second, with missed-beat reporting.
* `CDeltaTimer` — many timed events on one timer.

See [Time and timers](17-time-timers.md).

## 11.9 Troubleshooting

| Symptom | Cause |
|---------|-------|
| `E32USER-CBase 46` (stray signal) | `SetActive()` forgotten; AO not `Add()`ed; request issued with a non-member `TRequestStatus`; a request completed twice; cancelled/waited-on request signalled later |
| `E32USER-CBase 42` | `SetActive()` while already active (second request issued) |
| `E32USER-CBase 40` | AO deleted while active — destructor lacks `Cancel()` |
| `E32USER-CBase 47` | `RunL()` left and `RunError()` didn't return `KErrNone` |
| Thread hangs in `CActiveScheduler::Start()` | No request outstanding; or `Stop()` never called |
| `RunL()` never runs | No scheduler installed / started (console app), AO not added, `SetActive()` forgotten, or a higher-priority AO keeps completing |
| App freezes / `ViewSrv 11` | Long synchronous work or `User::WaitForRequest()` in the UI thread |
| `KERN-EXEC 3` in `RunL()` | Buffer passed to the async call went out of scope (it was a local) |
